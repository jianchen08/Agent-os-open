# AI 编码规则总纲

> 规则物料（可注入遵守）：编码/审查 agent 的总纲。核心编码/审查/测试规则的**权威载体**在
> `config/rules/`（`per_domain/coding_domain_rules.md`、`per_agent/*`、`testing_rules.md`），本篇不复制其条目，只写总纲与模式体系增量约束。
> 已落地不标；（规划中 P2/P3）= 已定稿未建成，不得按其编写集成。

## 一、目标三定律

1. **需求绝对忠诚**：每行代码可追溯到明确需求，禁止臆想"潜在需求"。
2. **架构绝对合规**：严守模块边界、接口契约、分层依赖，禁止跨边界偷跑。
3. **规范零容忍**：规范由工具与流程强制执行，不依赖 AI 自觉。

## 二、生成规则（编码 AI）

- 六条铁律：需求第一一字不增；最小输出与优先修改；严格复用（写新代码前先查现有接口）；尊重私有边界（只用公开接口）；错误要么处理要么传播（禁空 catch/仅日志）；放弃假兼容（无需求不留扩展点）。权威条目与量化阈值见 `config/rules/per_domain/coding_domain_rules.md` §一。
- 定边界四步：找散（同一概念多处出现 → 统一抽象）→ 找分叉点（调用方多状态判断 → 封装进模块内）→ 找谁该知道（不该知道者知道了 → 收回）→ 找变化方向（易变封装在内，稳定暴露为接口）。

## 三、审查规则（审查 AI，一票否决）

- 需求追溯：每行新增代码在需求/AC 清单中找依据，无依据强制删除。
- 架构四问：散点 / 分叉点 / 信息泄漏 / 变化方向，违者驳回。权威条目见 `config/rules/per_agent/code_reviewer_rules.md` §0。
- 铁面裁决：只认规则与自动化工具的客观结果，不接受"为了好看/稳妥"的主观辩解。

## 四、模式体系约束（横切，2026-09-15 定稿）

1. **前端冻结**：前端只准存在通用宿主件（一次性建成）；此后加/改模式必须**零 `frontend/src` diff**——模式能力 100% 由插件声明（`contributes`）+ 插件资源（webview/agents/pipelines/rules）交付。验收断言：mode_godot 立项时 frontend 无改动。凡方案出现"为某模式改前端"即违规，改为：补通用渲染能力（一次性）+ 包内声明/资源。
2. **引用语法**：跨包引用一律全限定 `plugin_id:resource`；包内引用裸 id + 相对包根路径；系统侧留守物走约定路径。禁止裸名引用他包资源；运行中任务 state 旧 ids 只读可解析，新写面一律新语法（随 P3 解析扩展落地，规划中 P3）。
3. **A/B 面**：模式包 `rules/`（口径规则）= A 面可进化（用户仓 git 管晋升/回滚/审计）；`policies/`（制度政策：金额分级表/签批链模板/安全红线）= B 面冻结。禁止把制度写进 rules、把口径写进 policies。
4. **进化两型**：改配置（`profile.yaml` / `agents/*.yaml` / `rules/*.md` / manifest fields）或改代码（`server.py` / `webview/*.html` / `pipelines/*.yaml`）；代码型过 promote 冒烟车道后与配置型同权晋升。共享骨架（内核、共享默认管道、前端宿主件、policies、eval_harness/题集）**非进化对象**。
5. **放文件即注册**：模式包内加 agent/编排/规则 = 放约定目录一个文件（`agents/` / `pipelines/` / `rules/` 约定扫描零声明，规划中 P2）；模式包资源禁止在 manifest 逐条声明，双声明面退役。

## 五、物理保险（规划目标，尚未落地）

> 现状：依赖 `config/rules/` + Ruff/mypy + CI 门禁 + Code Review 把关；以下强制机制未配置，本节为演进方向。

模块边界物理化（dependency-cruiser/no-restricted-imports 非法导入即编译失败）；架构自动化测试（pytest-archon 类，CI 必跑）；需求覆盖率扫描（无需求标注拦截）；冗余模式检测（空 catch/console.log/无 Issue TODO 拦截）。

# 前端打开任务对话标签——完整流程分析

> 分析时间：2026-06-04 | 代码库：frontend/src

---

## 一、架构概览

前端维护两套并行标签系统，通过 `pipelineId` 全局唯一路由键关联：

| 系统 | Store | 用途 |
|------|-------|------|
| **Agent Tab**（对话标签） | `agentTabStore` + `pipelineMessageStore` | L1/L2/L3 Agent 的对话标签 |
| **Workspace Tab**（工作区标签） | `layoutModeStore` | FiveSpaceLayout 中的文件编辑器等工具标签 |

**核心原则**：一个 `pipelineId` 在整个前端窗口中只对应一个 Agent Tab。

---

## 二、pipelineId 映射体系

```
pipelineTabMap     (agentTabStore)      → pipelineId → tabId      映射表
pipelineSessionMap (pipelineMessageStore) → pipelineId → sessionId 映射表
tab.pipelineRunId  (AgentTab 对象)       → Tab 直接关联的 pipelineId
```

反向查找（tab.pipelineRunId 为空时）：
```
遍历 pipelineTabMap → 找到 tid === tabId → 取出 pid
```

## 八、统一接口确认

**是的，所有"打开任务对话标签"的路径使用统一的接口。**

统一入口是 `services/pipelineNavigator.ts` 中的 **`navigateToPipeline(pipelineId, options?)`**。

```
外部调用者（仅 2 处）:
  ├─ FiveSpaceLayout.handleTaskNodeClick      → navigateToPipeline(pipelineRunId, {agentName, agentLevel, taskId, status})
  └─ useInteractionHandler.navigateToTab      → navigateToPipeline(threadId, {agentName, agentLevel})

内部调用者:
  └─ switchToTab() — TabBar 点击切换（不走 navigateToPipeline，直接操作 Store）
```

不同入口的差异仅在于 **上游预处理**（如交互入口先发 WS 响应、任务入口先过滤容器节点），一旦进入 `navigateToPipeline()`，后续逻辑完全统一。

# 提示词优化修改清单 v2

## 核心思路

- **工具描述** = 通用工具使用指导（参数、限制、格式）→ 所有用该工具的人都该知道的
- **提示词** = 角色行为决策指导（什么时候用、流程中怎么决策）→ 只有灵汐需要知道的
- **重复的以工具描述为准**，提示词中删除重复，只保留角色特定的决策原则

## 二、提示词修改清单

### 修改1：任务分类 — 删除与 task_submit 工具描述重复的参数约束

**位置**：第51-55行

**当前内容**：
```
- **即时响应**：简单问答、文件查看、单步操作 → 直接处理
- **普通任务**（task_scope=non_container）：功能实现、问题修复、文档编写 → 搜索资源后派发给专门 agent。**必须指定 target_type 和 target_id**。
- **容器任务**（task_scope=container）：一个软件项目、一个游戏、一部网络小说等复杂长期任务 → 创建容器组织子任务链。**不能指定 target_type 和 target_id**，容器只是一个组织框架，不直接执行。
```

**替换为**：
```
- **即时响应**：简单问答、文件查看、单步操作 → 直接处理
- **普通任务**：功能实现、问题修复、文档编写 → 搜索资源后派发给专门 agent
- **容器任务**：一个软件项目、一个游戏、一部网络小说等复杂长期任务 → 创建容器组织子任务链（仅组织框架，不直接执行）
```

**理由**：task_scope 的参数约束（必须/不能指定 target_type）已在 task_submit 工具描述的 allOf 中强制校验，无需在提示词重复。


### 修改2：参数决策 — 评估指标精简

**位置**：第79行

**当前内容**：
```
- **评估指标**：有文件产出 → file_check；涉及核心功能/影响项目质量 → 加 semantic_check
```

**替换为**：
```
- **评估指标**：按任务重要性选择，具体指标类型和格式参见 task_submit 工具描述
```

**理由**：task_submit 的 acceptance_criteria 描述已有完整的指标类型说明和使用原则（含"⚠️ Agent 评估器"警告），此处只需指向工具描述。


### 修改3：工作空间规则 — 删除与 task_submit 重复的通用说明，只保留业务规则

**位置**：第134-140行

**当前内容**：
```
### 工作空间规则

- workspace 参数指定目标项目路径，系统自动创建隔离的 worktree 副本
- 子任务自动继承父任务工作空间，不需设置 workspace
- 资源管理任务必须设置 `workspace="D:\myproject\container_08f57bc14532"`
- 工作空间在任务完成后清理，路径不再存在
- `inherit_workspace_from` 复用旧工作空间时，必须先用 `task_manage(get)` 确认旧工作空间仍存在
```

**替换为**：
```
### 工作空间规则

- 资源管理任务必须设置 `workspace="D:\myproject\container_08f57bc14532"`
- workspace 参数含义、子任务继承、inherit_workspace_from 等通用规则参见 task_submit 工具描述
```

**理由**：
- 第1条"workspace 参数指定目标项目路径..."→ task_submit 的 workspace 参数描述已覆盖
- 第2条"子任务自动继承..."→ task_submit 描述已说明"不设置时系统自动基于父容器空间创建"
- 第4条"工作空间完成后清理..."→ task_submit 描述已说明"清理后路径不再存在"
- 第5条"inherit_workspace_from..."→ task_submit 描述已说明"必须先用 task_manage(get) 确认"
- 只有第3条"资源管理任务必须设置特定路径"是角色特定的业务规则，必须保留


### 修改4：失败处理 — 精简为原则，详细步骤靠 task_manage 工具描述

**位置**：第142-152行

**当前内容**：
```
### 失败处理

收到子任务失败通知时，按以下策略逐步处理，禁止跳步：
1. `task_manage(get, include_details=true)` 查看实际执行情况
2. 根据证据判断根因（不要想当然）
3. **retry 优先**：方向对的问题一律 retry，保留工作空间+对话历史
4. retry 多次仍失败 → 考虑是否需要重新提交
5. 重新提交时如需延续旧成果 → `inherit_workspace_from`（但必须先确认旧工作空间存在）
6. 多次 retry 和重新提交均失败 → 通知人类，不要自行放弃或绕过
7. 人类确认无法解决 → `task_manage(action="fail_container")` 标记容器失败
8. 重新提交必须保持原流程位置不变，禁止跳步
```

**替换为**：
```
### 失败处理原则

- 详细处理步骤参见 task_manage 工具描述中的失败处理策略
- **角色特定原则**：
  - **Agent 不可更换**：任务链中指定的 Agent 任何情况下都不考虑换
  - **禁止跳步**：重新提交必须保持原流程位置不变
  - **兜底**：多次重试和重新提交均失败后必须通知人类，不要自行放弃或绕过
  - 人类确认无法解决 → `task_manage(action="fail_container")` 标记容器失败
```

**理由**：task_manage 工具描述已包含完整的①查详情→②判断根因→③retry→④重新提交→⑤通知人类的策略。提示词只需补充角色特定的约束（不换Agent、禁止跳步、兜底机制）。


### 修改5：定时/周期任务流程 — 大幅缩减

**位置**：第154-159行

**当前内容**：
```
## 定时/周期任务流程

1. **注册触发器**：`trigger_setup` 设置类型/频率/message + max_count 或 max_time
   - 相同间隔的活跃触发器优先用 `update` 延长
2. **触发后执行**：简单任务→直接执行；复杂任务→派发给对应 Agent
3. **停止条件满足时**：写执行总结报告到 `execution_summary_report.md`
```

**替换为**：
```
## 定时/周期任务流程

1. 用 `trigger_setup` 注册（参数和限制见该工具描述）
2. 触发后：简单任务直接执行，复杂任务派发给对应 Agent
3. 停止条件满足时：写执行总结报告到 `execution_summary_report.md`
```
### 修改3：resource_search — 无需修改

当前描述已包含完整的适用/不适用场景说明。

提示词硬约束第3条已有角色特定的搜索约束（"用户交代明确任务后直接派发，禁止自行搜索"），这是 Agent 行为约束，应留在提示词中，不应放入工具描述。

**结论：保持现状**

### 修改7：可扩展工具部分 — 只保留名字列表，删除搜索方式和可直接调用列表

**位置**：第216-222行

**当前内容**：

```
### 可扩展工具

需先 `resource_search(resource_type="tool", query="工具名")` 加载后使用：
```

```
### 可扩展工具（需 resource_search 加载后使用）

file_write, bash_execute, enhanced_search, web_search, task_evaluate, yaml_validate, fetch, design_generate, playwright_test, design_review, resource_merge
```

**理由**：
- 搜索方式是 resource_search 工具描述该说的事，提示词不重复
- "当前可直接调用"列表不需要写——工具描述已标注哪些在 tool_ids 中，模型调用时能感知到

## 三、工具描述修改清单

### 修改1：task_submit — 无需修改

当前描述已足够完善：
- workspace、inherit_workspace_from、isolation_level 等参数说明清晰
- acceptance_criteria 的评估指标指南（含分层评估原则和"⚠️ Agent 评估器"警告）已覆盖提示词中删除的内容
- allOf 约束已强制校验 task_scope 规则

**结论：保持现状**

### 修改2：task_manage — 无需修改

当前描述已包含：
- 完整的失败处理策略（①~⑥）
- inject 消息粒度规则（区分4种触发性质）
- complete_container/fail_container 说明

**结论：保持现状**

### 修改3：resource_search — 建议微调

**当前描述**中的"适用场景"和"不适用场景"与提示词的"第二步：资源匹配"有轻微重叠。

**修改建议**：

在描述的"注意事项"部分追加一条：

```
- 灵汐（L1）有额外的搜索约束：用户交代明确任务后直接派发，禁止自行搜索。只有用户要求查、需要澄清、映射表无匹配项时才搜索
```

**理由**：这条约束是角色特定的，但放在工具描述中可以确保即使角色提示词中没有提到，也能起到提醒作用。不过如果提示词硬约束第3条已足够明确，此条可不做。**优先级低，可做可不做。**

### 修改4：trigger_setup — 无需修改

当前描述已包含：
- 完整的参数限制（最大24小时、最小10秒、最多10个等）
- 适用/不适用场景
- 注意事项

**结论：保持现状**

### 修改5：human_interaction — 无需修改

当前描述已包含完整的模式说明和参数说明。

**结论：保持现状**

# 打包发版循环问题与方案（2026-09-29）

> 打包发版环节六工具组的来龙去脉总览。每个脚本的 §5.x 子节；post-install
> 阶段单列 §6。受众：CI 维护者 + 装机版验收者。

## §1 背景

装机版（NSIS / DMG / AppImage）发版循环里出过三类反复的退化（2026-09 受
CI 镜像、平台限额窗、Defender 实时扫描三轮实测固定）：

1. **脏树 + 内核陈旧** — `electron-builder` 对工作区 dirty 与 `kernel.exe`
   mtime 零校验，R299 实证并行 WIP 被摄入、`kernel.exe` 比最新内核源旧一代；
2. **双 agent 抢装 + 裸拉** — 平台限额窗杀进程前后无人互斥，C1 时区差异下
   找日志扑空，运维/发版两边各自三件套（人肉盘点 / handoff 缺失 / 锁缺失）；
3. **装回裸奔 + 安装位形态漂移** — 装机后应用起不来、`%APPDATA%\agentos`
   结构漂移、venv 缺位无业务面回声——装机末无结构化冒烟链路冗余。

裁决线：**fail-closed + 工具三件套**——所有能机器判据的退化都先在
`electron:build` 链首 fail-closed，机器无法判的退化走单写者互斥锁
（ops_lock）+ 五层探针（health_probe）+ 装后冒烟（post_install_smoke）
三件套兜底；六工具一总页就靠本节。

## §2 架构：发包链路节奏

```
[开发]                              [发版]
源码/内核                            zip/dmg/AppImage
   │                                    │
   ▼                                    ▼
sanitize ─► kernel_freshness ─► clean_tree ─► vite/tsc ─► electron-builder ─► check_packaged_layout ─► packtest_smoke
                                                                    ↓
                                                          安装到 $INSTDIR
                                                                    ↓
                                                          post_install_smoke ─► health_probe ─► ops_lock(运维锁)
```

`sanitize`/`kernel_freshness`/`clean_tree` 在 build 链首（fail-fast）；
`check_packaged_layout`/`packtest_smoke` 在 build 链尾（产物校）；
`post_install_smoke`/`health_probe`/`ops_lock` 在装机链路（部署 + 运维）。

## §3 设计原则

- **fail-fast > fail-late**：能让 build 链直接挡住的退化不留给装机端；
- **互斥优先于乐观并发**：B1 双 agent 抢装靠 ops_lock 文件锁，不靠 git status；
- **探针零副作用**：health_probe 只读（DB ro 连接 / auth 纯 roundtrip），
  部署机器可随时执行不丢任务；
- **装回自动有结构化尾迹**：post_install_smoke 三步 API 冒烟 + 退出码，
  安装脚本（NSIS customInstall / `python install.py`）可消费其退出码拒绝
  装回裸奔。

## §5 工具细节

### §5.1 `check_kernel_freshness.py` — 内核新鲜度校验（A1）

- **位置**：`scripts/check_kernel_freshness.py`
- **门位置**：`electron:build` 链首（sanitize 后第二步）
- **判据**：
  1. `git status --porcelain -- kernel/` 非空 → fail（HEAD 落锁后源改动）
  2. `kernel/target/release/agentos-kernel.exe` mtime 早于 `git log -1 --format=%ct -- kernel/` → fail（陈旧）
- **被否方案**：
  - **人肉 `touch`**：修完内核忘 touch 兜底撑塌 — R299 实证把陈旧内核当 release 用
  - **二进制字符串 grep 版本号**：被 strip / 加壳 / 编译器内联一打就漂

### §5.2 `check_clean_tree.py` — 脏树检查（A2，goreleaser dirty-check 范式）

- **位置**：`scripts/check_clean_tree.py`
- **门位置**：`electron:build` 链首（sanitize 后第三步）
- **判据**：`git status --porcelain` 对**打包相关路径**（`package.json`、
  `electron/`、`frontend/src`、`frontend/public`、`plugins/shared`、
  `config/`、`kernel/`）非空 → fail
- **被否方案**：
  - **不校验兜底**：`electron-builder` 对 dirty 零校验，R299 实证带过 WIP
  - **`--allow-dirty` 模式常态化**：受管还原会把 worker 状态抹掉致包内容漂
  - **检查全工作区**：`docs/` `tests/` `logs/` `data/` 等非打包路径误伤太宽
- **逃生口**：`--allow-dirty` 单次硬印「未验证」横幅，禁止常态用

### §5.3 `ops_lock.py` — 运维操作互斥锁（B1/B2）

- **位置**：`scripts/ops_lock.py`
- **覆盖**：shell 操作层（install / uninstall / 重启 / 镜像同步类）
- **语义**：取锁（O_EXCL 锁文件 + PID 探活）+ 抢占（持锁者死亡后租约过期
  自动可抢占）+ 审计（`audit.log` 留痕）
- **被否方案**：
  - **不互斥靠 git status**：双 agent 同时装致 install dir 漂移
  - **互斥靠全局 mutex**：跨进程跨机器不可见
  - **无审计**：B2 半途无收尾不可发现

### §5.4 `health_probe.py` — 五层 readiness 探针（B3/C1/E3）

- **位置**：`scripts/health_probe.py`
- **层**：
  - L0 进程：agentos-kernel / 灵汐助手.exe 进程树 + ParentProcessId 孤儿判定
  - L1 端口：9101（dev 9100）可达性 + WS ticket 探活
  - L2 日志：`logs/` 路径、时间格式化（治 C1 UTC 找日志扑空）
  - L3 业务：login + plugins/hosts + ws/chat（纯读、不写）
  - L4 资源：DB ro 探活 + config 完整性 + 磁盘剩余
- **原则**：只读零副作用；登录探活为纯 auth 往返无数据写面
- **被否方案**：
  - **业务面写冒烟**：装后探针不该改状态，治标不治本
  - **不带时区格式化**：C1 找日志扑空（UTC 时间戳 vs 本机时间）

### §5.5 `write_handoff.py` — 任务交接档案（C3/E1）

- **位置**：`scripts/write_handoff.py`
- **模板**：`docs/working/templates/task_handoff.md`
- **五要素**：任务 / 进度 / 环境态（含密钥位置 + 端口进程占用两强制记录面）/ 风险 / 下一步
- **触发**：长跑 agent 每完成里程碑回写一次（`--force` 覆盖）；主会话盘点
  = 读 handoff 目录 + health_probe.py
- **被否方案**：
  - **靠 git commit message**：commit 历史是结果视图，盘点需 plan agent
  - **靠 chat 滚动**：限额窗杀进程即丢

## §6 装机链路

### §6.1 `check_packaged_layout.py` — 装机结构校验（A3）

- **位置**：`scripts/check_packaged_layout.py`
- **门位置**：`electron:build` 链尾（产物校，独立 gate 不并入链）
- **判据**：
  - `_host/.venv/Scripts/python.exe` 在位
  - `host_group=light_stable` 成员插件不带自有 `.venv`（合宿主 venv）
  - 成员 `pyproject.toml` 依赖在共享 venv 内可达
- **被否方案**：
  - **运行时校验**：装回裸奔已发生，业务面投影已存

### §6.2 `packtest_smoke.py` — win-unpack CDP 冒烟

- **位置**：`scripts/packtest_smoke.py`
- **门位置**：`electron:build` 链尾（产物校，独立 gate 不并入链）
- **判据**：
  - app://bundle 加载
  - React mounts to #root
  - SPA deep-link `app://bundle/login` resolves
  - `/api/v1/auth/me` 返回 non-text/html（代理上游非静态 fallback）
- **被否方案**：
  - **靠人工启动**：人肉开 GUI 点四步——复现成本高 / CI 不可消费
  - **靠 Playwright over electron 出 WS**：electron-builder 已经把 WS 暴露
    在 CDP，绕 Playwright 直接 CDP 更简洁

### §6.3 `post_install_smoke.py` — 装后冒烟（A3 退位）

- **位置**：`scripts/post_install_smoke.py`
- **门位置**：装机链路末（应用 install 内核）—**不并入 build 链**
- **三步**：
  1. 登录：`POST /api/v1/auth/login`（admin + 口令）
  2. 插件宿主面：`GET /api/v1/plugins/hosts`
  3. WS roundtrip：`/api/v1/ws-ticket` → `ws://.../ws/chat?ticket=...` → `user_input` → `stream_end`
- **退出码**：0=green / 1=assertion fail / 2=unreachable
- **被否方案**：
  - **靠人肉点**：C3 装回裸奔的诊断面已收缩
  - **不写退出码**：CI 装机脚本本应能消费退出码拒绝装回

## 3. 逐构造对比表

| 构造 | Python（触发器） | Rust（内核 DSL） | 关系 |
|---|---|---|---|
| 比较 `== != > < >= <=` | 有（单次，不链接） | 有（单次，不链接） | 一致 |
| `and / or / not / (...)` | 有，优先级 or<and<not | 有，同优先级 | 一致 |
| 短路求值 | 有 | 有 | 一致 |
| 字符串字面量（单/双引号，无转义） | 有 | 有 | 一致 |
| 数字字面量（整数/小数，无符号） | 有（int 归一） | 有（i64 优先） | 一致 |
| `True/False/None` 大小写不敏感 | 有 | 有 | 一致 |
| 列表字面量 + 列表深相等 | 有 | 有 | 一致 |
| 点链 `a.b.c` / 下标 `a[i]`/`a['k']` | 有 | 有 | 一致 |
| 缺失键/越界/形态不匹配 | → None → 比较假 | → Null → 比较假 | 一致 |
| 扁平点号键解析 | 全路径平键优先，嵌套回退（86-109） | **前缀平键超集**：任一前缀命中即下钻（119-144） | Rust ⊇ Python（Rust 更宽，覆盖"平键持 dict"生产形态，condition.rs:1024-1061 实测） |

| 链式比较 `a<b<c`、`in`、方法调用、dict 字面量、注释 | 无（语法错） | 无（语法错） | 一致（都无） |

### 3.5 语义差异（语法同但求值结果可能不同）——迁移的真正风险面

1. **跨类型数字相等**：Python `True == 1` → True、`1 == 1.0` → True；Rust `json_eq` 走 serde_json `PartialEq`，`Bool(true) != Number(1)`、`Number(1) != Number(1.0)`（serde_json-1.0.150 number.rs:37-46 跨变体 `_ => false`）。⚠️ condition.rs:905-908 的注释声称"数字跨整数/浮点等价：serde_json 的 Number 已处理 1 == 1.0"——**与实现相反，属注释级契约与实现的背离**（891 行宣称"语义对齐 Python"）。
2. **布尔参与大小比较**：Python `True > 0` → True（bool 是 int）；Rust `json_cmp` 对 Bool 返回 None → False（condition.rs:913-928）。
3. **大整数精度**：Rust `json_cmp` 把数字统一转 f64 比较（916-921），|i64| > 2^53 有精度损失；Python 整数精确比较。存量无此形态（见 §4）。

## 4. 存量表达式盘点（迁移对象的真实面）

- 触发器持久化在 pipeline_state（`task.trigger.registry.*`，manager.py:47, 659）；查 dev 库 `agentos_kernel.db`：**0 条含 condition_expression 的存量触发器**（2026-10-02 只读查询）。即代码库/文档内的表达式就是全部已知存量面。
- 用户侧契约示例（`plugins/shared/tools/triggers_ext/tool.py:83,210`）：`task_status == 'pending'`（下划线平键示例；实际聚合行键为 `task.status` 扁平点号键，task_evaluate/tool.py:1370-1373、manager.py:289）。
- 测试/文档中的全部条件表达式形态：`ready == true`、`flag == 1`（state 侧为 int 1，test_triggers_ext_coverage_gaps_h.py:169-171）、`task.status == 'failed'/'completed'`、`x == 1`、`xs[1] == 2`、`m['k'] == 'v'`、`(a == 1 or b == 99) and c > 3`、`x > 1.5`、`x == 1.50`、`x > 1.5`、`raw_tool_calls != []`。
- **仓库内无 CJK 标识符条件、无算术条件、无 len() 用于触发器**；跨类型相等（bool==1、int==float）仅出现在 state 值与字面量同型的写法中（`flag == 1` 两侧均为 int，两侧求值一致）。
- 对照：内核管道 DSL 的真实存量（config/pipelines/*.yaml）反而**已用上** Rust 扩展语法——`config/pipelines/autonomous.yaml:34` 的压缩粗门公式（算术 + `len(messages)`）在 Python 求值器下根本无法解析，进一步佐证 Rust 是超集。

## 6. 结论与迁移建议

**结论：Python 是 Rust 的真子集（语法层面），另加三处点状语义差（§3.5）。** 具体构成：
- 语法超集方向 1（Rust 多）：算术 `+ - * /`、内建 `len()`、前缀平键路径解析；
- 语法超集方向 2（Python 多，唯一）：Unicode/CJK 标识符（及全角数字边缘）；
- 语义差：跨类型数字相等（`True==1`/`1==1.0`）、bool 大小比较、大整数 f64 精度——其中第 1 项连 Rust 侧自己的注释（condition.rs:905-908）都宣称对齐 Python 而实现未跟上。

**迁移判定：直接迁移可行，不需要写一次性表达式转换器**（存量表达式全部落在 Rust 文法内且逐条静态判定等价，§5.1）。建议形态：

1. **推荐：直接迁移 + 内核求值器小幅语义补齐（一个版本期内保留 Python 解析器做影子比对可选）**
   - 内核 `json_eq` 补数字跨 int/float 归一相等（bool 不并入数字，与 Python `True==1` 的取舍需一次 ADR 拍板——补齐即让实现追上 condition.rs:905-908 已宣称的契约）；改动点集中、带测试约 0.5 人日。
   - CONDITION 注册期校验从插件 `compile_condition`（manager.py:145-150）切换/并存为内核 `parse_condition`，CJK 标识符等 Python-only 构造在注册期显式报错（存量为零，无破坏面）。
   - 求值期兜底契约对齐现状：表达式编译/求值异常 → False + debug 留痕（condition_parser.py:397-416 语义），不沿管道加载期的"报错炸编译"路径。
   - 若求值上收走内核 capability 服务，注意轮询节奏（5s/轮，manager.py:888-902）带来的往返成本；表达式结果只依赖行数据，可按行批量求值一次往返。
2. 备选：保留 Python 解析器一个版本期做影子比对（双跑日志差分）后再切——仅在担心语义差未被发现时需要，+1 人日。
3. 被否方向：写转换器把 Python 表达式改写成 Rust 文法——无必要，Python 侧没有任何 Rust 不接受的存量构造需要改写。

**工作量估计（不含触发器整体上收内核的轮询/边沿/注入重构，仅"条件求值上收"）：**
- 内核求值入口暴露（capability/服务）+ 注册期校验接入：0.5–1.5 人日
- 插件侧切换（`_eval_condition`/`evaluate_condition_rows` 走内核）+ 兜底契约 + 测试迁移：1–2 人日
- 语义补齐（json_eq 跨类型）+ 差异回归测试（bool/float 相等、平键两形态、CJK 注册报错）：0.5–1 人日
- **合计约 2.5–4.5 人日**；若选择影子比对过渡 +1 人日；若把整个触发器循环（轮询/边沿检测/注入）一并上收内核，另行评估（该范围超出本核查）。

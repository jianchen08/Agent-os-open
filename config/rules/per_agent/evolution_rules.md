# 自进化触发规则

## 1. 何时识别能力缺口

Agent 在以下三种场景应识别能力缺口：

### 1.1 工具未找到

当 Agent 尝试调用一个不存在的工具时（ToolCore 返回"工具未找到"错误），这是一个明确的能力缺口信号。

**Agent 应做的**：
- 不要直接向用户报告"我做不到"
- 调用 `EvolutionTrigger.check_tool_not_found(tool_name, tool_args)`
- 根据触发结果决定下一步：
  - 触发成功 → 使用新生成的工具重试
  - 触发失败 → 向用户说明情况
  - 建议模式 → 向用户转述建议

### 1.2 任务无法完成

当 Agent 在执行任务过程中发现自身缺少某种能力（无法通过现有工具组合完成），应主动报告。

**识别信号**：
- 所有可用工具都无法实现某个关键步骤
- 需要的数据格式/协议不被现有工具支持
- 需要与外部系统交互但缺少对应连接器

**Agent 应做的**：
- 调用 `EvolutionTrigger.check_capability_gap(description, context)`
- description 应精确描述缺失的能力，如"PDF 文件合并能力"

### 1.3 用户明确请求新能力

用户直接请求一个系统目前不具备的功能。

**Agent 应做的**：
- 确认是真正的能力缺口（而非用户误操作或不了解已有功能）
- 调用 `EvolutionTrigger.check_capability_gap(description, context)`
- context 中包含用户的原始请求

## 2. 如何描述能力缺口

能力描述应遵循以下结构化格式：

```
能力描述: [动词] + [对象] + [条件/约束]
```

### 2.1 好的描述

| 描述 | 为什么好 |
|------|---------|
| "PDF 文件合并能力" | 动词+对象，清晰明确 |
| "将图片从 PNG 转换为 WebP 格式" | 包含具体格式约束 |
| "执行 Python 代码并返回结果" | 动作+输入输出 |
| "连接 MySQL 数据库并执行查询" | 明确外部系统和操作 |

### 2.2 差的描述

| 描述 | 问题 |
|------|------|
| "做不了" | 没有描述具体能力 |
| "功能不够" | 过于模糊 |
| "需要更多工具" | 未指定什么工具 |
| "系统太弱" | 主观评价，非能力描述 |

### 2.3 context 应包含的信息

```python
context = {
    "task_id": "当前任务 ID",         # 可选，用于追踪
    "trigger_source": "tool_not_found | capability_gap | manual",
    "tool_name": "缺失的工具名",      # 工具未找到时
    "tool_args": {},                  # 工具参数
    "priority": 1-10,                 # 优先级（1 最高）
    "required_by": "调用方标识",      # 可选
}
```

## 3. 触发模式

### 3.1 自动模式（AUTO）

- 检测到能力缺口后**直接执行**进化流程
- 适用于：可信环境、低风险能力
- 频率限制：默认每分钟最多 3 次
- Agent 拿到结果后可直接使用新能力

### 3.2 建议模式（SUGGEST）

- 检测到能力缺口后**只返回建议**，不执行进化
- 适用于：生产环境、高风险能力、需要人工确认
- Agent 应向用户转述建议，由用户决定是否执行

### 3.3 模式切换

触发模式由系统配置决定，Agent 不应自行切换模式。

## 4. 安全边界

### 4.1 可自动进化的能力

以下类型的能力可以自动触发进化（AUTO 模式）：

- 文件操作类工具（读取、搜索、复制、移动）
- 数据格式转换（JSON/YAML/CSV）
- 文本处理（正则匹配、模板渲染）
- 命令执行封装（在安全审查通过的前提下）
- API 调用封装（公开 API、无敏感数据）

### 4.2 需人工确认的能力

以下类型的能力**必须**在 SUGGEST 模式下或人工确认后才能进化：

- 网络监听/端口操作
- 数据库写操作
- 系统级操作（进程管理、用户管理）
- 涉及密钥/凭证的操作
- 文件删除（批量/递归）
- 任何可能产生不可逆副作用的操作

### 4.3 禁止进化的能力

以下能力**绝对禁止**通过自动进化获取：

- 绕过安全审查的代码
- 提权操作
- 数据窃取/外传
- 删除系统关键文件
- 修改 Agent 自身的核心配置

## 5. 与现有系统的集成

### 5.1 ToolCore 集成点

```
ToolCore._execute_single_tool()
  → 工具未找到
  → _try_auto_load_tool()        # 已有：尝试自动加载
  → EvolutionTrigger.check_tool_not_found()  # 新增：检查进化触发
  → 根据结果决定是否重试
```

### 5.2 Agent 执行循环集成点

```
Agent.execute_task()
  → 发现无法完成某步骤
  → EvolutionTrigger.check_capability_gap()
  → 触发成功 → 重试该步骤
  → 触发失败 → 调整策略或报告用户
```

### 5.3 EventBus 事件

触发器会通过 EventBus 广播以下事件：

| 事件类型 | 触发时机 | 数据 |
|---------|---------|------|
| `evolution.triggered` | 能力缺口被检测到 | TriggerEvent.to_dict() |
| `evolution.completed` | 进化流程完成 | EvolutionResult |

## 6. 示例交互

### 示例 1：工具未找到自动进化

```
用户: 帮我搜索项目中所有包含 TODO 的文件
Agent: 调用 file_search 工具 → 工具未找到
Agent: 调用 EvolutionTrigger.check_tool_not_found("file_search", {"pattern": "TODO"})
系统: [进化触发] 分析缺口 → 生成 file_search 工具 → 安全审查 → 热加载
系统: 进化成功，已加载插件 'file_search'
Agent: 使用 file_search 工具重试 → 返回搜索结果
```

### 示例 2：建议模式

```
用户: 帮我把数据库里的数据导出为 Excel
Agent: 发现缺少 Excel 导出能力
Agent: 调用 EvolutionTrigger.check_capability_gap("Excel 导出能力", {...})
系统: [建议模式] 检测到能力缺口，建议进化以获取 Excel 导出能力
Agent: 我目前缺少 Excel 导出能力。系统建议为此生成一个专用工具，是否允许？
用户: 可以
Agent: 手动触发进化 → 生成工具 → 执行导出
```

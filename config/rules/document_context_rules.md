# 上下文读写规则

> 先读后动手；读和写是同一张索引：每个位置，什么时候读、什么时候写。

## 注入面（已在上下文，禁止获取）

| 判定 | 动作 |
|---|---|
| 信息已出现在上下文（全局宪法 AGENTS.md、任务书正文等已注入内容） | 直接使用，禁止对已注入内容再调 `file_read` |
| 任务书给出文件指针（技能 SKILL.md、设计真值、ADR） | 按指针 `file_read` 读全文——唯一获取例外 |

## 统一索引（读 × 写）

| 索引 | 内容 | 什么时候读 | 什么时候写（要求） |
|---|---|---|---|
| 全局宪法 AGENTS.md | 全局铁律与常驻上下文 | 已注入，不读 | 全局性最重要的内容放这里；改动走评审 |
| 任务书 requirement | 范围 / AC / 真值指针 / 签发测试 | **恒先读** | 调度方派发时写：四件套 + 签发记录；执行方只读 |
| `docs/decisions/` ADR | 非平凡决策与被否方案 | 动手前先查被否方案 | 非平凡决策评审通过后写：五段，被否强制 |
| `docs/working/` 设计真值 design | 模块契约（需求/逻辑/结构三节，实现禁写） | 进模块前（指针直达） | 模块有长期契约时写：truth_for 指向代码实体 |
| `docs/working/` 台账 ledger | 进度唯一锚 | 接续 / 排查时 | 接活立账时写：四节（轮次/已修/遗留/验收） |
| `docs/working/` 方案 plan | 复杂任务的评审载具 | 评审 / 接手时 | 复杂任务评审前写：八件（含被否方案）；评审后拆解 adr + design 本体归档 |
| `docs/working/` 报告 report | 审查 / 验证 / 调研结论 | 验收时 | 审查方写：只写未修项；产出即终态 |
| `docs/guides/` | 使用指南 | 面向使用方 | 面向使用方的操作说明 |
| 源码 + 测试 | 实现与验收锚 | 动手时 | 执行方写；签发测试只读，禁自产验收证据 |

**元数据格式**（每份新文档头部必带，只此三字段）：

```yaml
---
doc_id: 20261022-<slug>        # 唯一 ID = 图节点 ID
type: plan|adr|ledger|design|requirement|report
status: draft                  # draft | active | superseded | archived
---
```

**关系用双链**：正文内 `[[doc_id]]` / `[[路径]]` 指向相关文档、代码、文件——取代、依据、真值指向、验收对象一律用双链表达（类似 Obsidian 双链），图由双链机械扫描生成、双向可达。

## 强制规则

**读**：任务书恒先读；指针直达属合法跳级；无指针按 顶层（ARCHITECTURE/ADR）→ 模块级（设计真值/指南）→ 实现级（源码/测试）递进；按索引定位，禁盲目全项目搜索；跨模块修改同读相关模块。

**写**：新文档必带 frontmatter（type / status / truth_for）；改接口/配置必须同步更新相关文档；非平凡决策必落 ADR；执行方**禁改签发测试、禁自产验收证据**、审查方盲审写 report；中间产出进 `docs/working/` 随归档清理。

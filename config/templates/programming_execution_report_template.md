# 编程编排执行报告模板

<!--
============================================================
【模板是什么】
编程编排任务的结构化执行报告，以修复清单为核心，强制记录每个修改的具体内容、验证动作和验证结果。

【模板的作用】
1. 防走过场 — 强制要求记录实际代码修改（而非仅分析建议），确保修复真正落地
2. 验证可追溯 — 每个修改都有对应的验证工具、验证动作和具体数据
3. 结果可量化 — 验证结果必须包含具体数据（测试用例数、通过率等），禁止模糊声称
4. 质量可评估 — 结构化格式让评估者能快速判断验证是否充分

【如何使用本模板】
1. 按章节顺序填写，[必填] 章节不可省略
2. 修改清单的每一行必须对应一个实际的代码变更
3. 验证结果必须包含具体数据，不允许仅写"已验证"或"通过"
4. 保存到任务工作空间根目录

【适用场景】
- 编程任务的编排执行报告（路径 A/B/C/D 均适用）
- 修复/优化/验证类任务的执行结果汇总
- 功能开发完成后的质量汇总

【占位符说明】
- {xxx}：需要替换为具体内容的占位符
- [必填]：必须填写的章节
- [可选]：按需填写的章节
============================================================
-->

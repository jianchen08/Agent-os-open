# ZCode 应用档案

> 派发前先加载方法论：`skills/credit-delegation/SKILL.md`（接口优先级、三阶段协议、token 经济学）。本文件只记录 ZCode 的五要素与实测锚点。工具用 computer_use 上游原名：App/Snapshot/Click/Type/Shortcut/Wait。

## 五要素

| 要素 | 内容 |
|---|---|
| 窗口匹配 | 窗口清单含 "ZCode"；多窗口取对话主窗（含会话标题者） |
| 输入定位 | Snapshot 找输入框元素；实测锚点 (1115,903)（随窗口位置漂移，仅参考） |
| 发送动作 | 点"发送"按钮；**ZCode 忙时按钮变"加入队列"**——点击即排队，输入框清空=入队成功 |
| 完成信号 | ①派发简报约定的结果文件出现（首选）②队列区条目消失 ③该任务流式输出结束 |
| 结果契约 | 简报末尾约定："完成后把结果摘要写入 %USERPROFILE%\agentos_dispatch\zcode-<任务名>.md" |

## 实测怪癖（2026-09-18 真机跑通）

- `Click`/`Type` 的 `label` 参数是 **UIA 元素整数 id**，不是文本；`Type` 必须 `loc` 或 `label` 二选一。
- 中文等非 ASCII 由上游自动走剪贴板粘贴（会覆盖用户剪贴板，先告知）。
- ZCode 忙时不要反复发送：确认入队后按方法论的"失聪等待"收工，等结果文件。

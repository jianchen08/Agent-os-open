# 提示词 / Skill 规则工程方法论 v1.1

> **本技能是流程指引，不是逐条打勾清单**：按场景判断使用，遇不适用情况保持裁量，不机械执行。

## 适用范围

LLM 系统提示词、Skill 规则、agent 工作流、RAG 指令、工具调用规范。
目标：省 token、准确、无歧义、可调试、可回归、可版本化。

## 一、总原则

1. **提示词 = 接口规格**：条件可判定、动作可执行、结果可验证、解释唯一。
2. **改提示词 = 改代码**：先复现失败，再定位最小部分，做最小补丁，最后回归测试。
3. **一次只改一个因果维度**：多版本并行（Candidate Beam）时，每个候选也各只改一处，否则无法归因哪个修改有效。
4. **优先级固定，且在使用前声明**：
   - 跨类冲突：P0 安全 > P1 任务正确性 > P2 输出格式 > P3 风格；高覆盖低。
   - 文档内冲突：规则 > 流程 > 示例。**示例没有优先级位，永不推翻规则**——示例与规则冲突时改示例或删示例，规则为准。
   - P# 只标注在存在真实冲突可能的规则上；无冲突可能的普通规则不强制编号。
5. **术语全局唯一**：关键名词定义一次全文一致；禁用「它/该/这个」跨句指代。
6. **输出契约兜底**：格式、字段、长度必须可验证；空/超长/失败/未知/冲突输入的行为必须定义。
7. **版本化**：每次变更留一行记录（格式见 §五），能回滚。

## 二、新写：契约结构（六层 + 两个可选层）

```text
目标：一句话。
范围：做什么；非目标：不做什么（任务偏移先改这里）。
术语：A=…；B=…。
规则：当<可判定条件>，必须<可执行动作>；否则<默认>。
禁止：<禁止项> → <替代动作>（只写"不要"不给出路 = 不合格）。
输出：格式、字段、长度、异常输入处理（写得出验证方法才写）。
可选-流程：S# 输入→动作→输出→失败分支→下一步条件（多步骤任务时）。
可选-示例：仅边界例/反例，每类 ≤1；示例集跨输入类型/长度/复杂度多样化（防锚定）。
```

## 三、规则写法

- 一条规则只做一件事；句式「当 X → 必须 Y；否则 Z」。
- 用 **必须 / 禁止 / 可**；黑名单：尽量、适当、可能、一般来说、考虑、酌情、相关。
- 量化只落在**模型输出可控维度**：字数、句数、条目数、轮次、字段名、必须包含的标记。时延、耗时等模型不可控量不得作为提示词量化指标。
- 肯定句优先；禁止必须配替代动作。
- **形态双轨**：契约型用规则行，流程型用编号步骤或表格。合规判据是「可判定/可执行/可验证」，不是句式——表格行、流程步与规则行同等对待。

## 四、省 token

- 删：客套、解释、重复、模型已知常识（通用教科书代码、概念科普不入提示词）。
- 用：列表、短句、符号 → = ≠ ≤ ≥。
- 合并同条件或同动作规则；用编号引用，不复述。
- 变量占位：`{input}`、`{lang}`、`{{path:…}}`。
- **冗余检查（瘦身测试）**：删去 30% 内容后行为契约不变 → 说明有冗余，删之。这是冗余检测，不是健壮性测试。

## 五、修复：症状 → 部分 → 改法

| 症状 | 先改 | 改法 |
|------|------|------|
| 任务偏移 | 目标/范围 | 缩非目标，重写目标一句 |
| 理解不一致 | 术语 | 加定义，全文统一替换 |
| 条件歧义 | 规则 | 量化条件，黑名单词清零 |
| 规则冲突 | 规则 | 加优先级声明，高覆盖低 |
| 步骤漏/乱 | 流程 | 编号步骤，加输入输出和前置条件 |
| 循环/不终止 | 流程 | 加最大轮次、终止条件 |
| 工具调用错 | 流程 | 明确调用条件、参数、失败分支 |
| 格式漂移 | 输出/规则 | 固定字段、长度、JSON schema |
| 风格不对 | 示例/规则 | 加边界示例 + 禁止项 |
| 边界错 | 示例/规则 | 只加边界例或反例 |
| 引用断链/事实锚点过期 | 事实锚点 | 引用带路径；落档前验证目标存在（ls/读原文），过期锚点改为去路径化表述或更新为现状 |
| 多副本漂移 | 副本结构 | 单源 + 薄指针（见本仓 credit-delegation 先例），禁止多处存全文 |
| 回归口径不一 | 评估节 | 阈值与用例集规模集中定义一处 |

### 修复流程（单失败快路径）

1. 收集失败样本：输入、输出、期望、环境。
2. 最小复现：去掉无关上下文，仍失败才改。
3. 归类到部分：目标 / 术语 / 规则 / 流程 / 示例 / 输出 / 上下文。
4. 写测试：原失败 + 相似 + 反例 + 空/超长/异常。快速迭代默认 5–10 例，至少 1 例留出。
5. 最小修改：只改归类部分。
6. 回归：新旧版本同一评估集跑分对比，涨了才保留；否则回滚。
7. 版本记录一行：`v# 日期 | 改了什么 | 归因(失败签名) | 前分→后分 | 回滚点`。

```text
修复模板
失败：…
归类：规则/流程/示例/…
最小改：…
测试：原失败 + 相似 + 反例 + 异常
影响：…
```

### 批量循环（升级条件：失败成簇 ≥3 类，或快路径 2 轮未收敛）

Baseline（代表性样本跑当前版，记录评分与证据）→ Failure Clustering（先归类再编辑：歧义/缺约束/规则冲突/示例错配/工具指令弱/停止条件弱/膨胀；同根因统一处理）→ Textual Gradients（批评写成定向编辑，如「明确何时应先询问再行动」；禁「更好」「更清晰」）→ Candidate Beam（2–4 个候选，各改一个维度，保留 1 个低风险对照）→ Holdout 验证（留出集重放原始失败，确认无回归）→ 停止条件（分数连续持平 / 编辑震荡 / 剩余失败源于模型或工具限制 / 过拟合评估集）。

**通过口径**（集中定义，全流程引用）：评估集 ≥10 例（40% 正常、30% 边界、15% 对抗、15% 回归），评分阈值 0.80+，含 ≥1 留出例。回归=同集跑分不降 + 原失败例通过。

## 六、无歧义检查清单

- 条件能判真假？动作能执行？输出能验证？解释唯一？
- 与其他规则冲突？优先级已声明？示例是否越位推翻规则？
- 空/超长/失败/未知/冲突输入有定义？
- 术语全文一致？黑名单词清零？
- 删 30% 后契约不变 → 删冗余。
- 只改了一个变量？能回滚？

## 七、常见失败模式速查

| 失败模式 | 症状 | 修复 |
|----------|------|------|
| 指令覆盖 | 模型忽略约束 | 约束前置，关键指令前载和后载 |
| 格式漂移 | 输出结构不稳定 | 加 JSON schema，固定字段 |
| 谄媚 | 模型附和错误前提 | 加「挑战假设」指令 |
| 冗长膨胀 | 输出太长淹没答案 | 加字数上限，删示例解释 |
| 幻觉 | 捏造事实/引用/代码 | 加「仅引用提供的上下文」+ 来源标注 |
| 锚定效应 | 首个示例主导输出风格 | 多样化示例，加「每个输入独立」 |
| 中间丢失 | 中间指令被忽略 | 关键指令前载和后载 |

## 八、与本仓规则的衔接

- 信息诚实：事实与来源标注按 `config/rules/information_integrity_rules.md`；本方法论中一切「事实锚点」引用同样适用（写路径前先验证存在）。
- 防过拟合：自进化提案的「禁止哪里错补哪条」「新规则必须表述为通用规则」与 §五 Holdout 同源，见 `config/self_evolve/rules/evolution_rules.md`。
- 双真值防线：方法论/技能类物料单源放 `skills/`，其他环境用薄指针引用（credit-delegation 先例）。

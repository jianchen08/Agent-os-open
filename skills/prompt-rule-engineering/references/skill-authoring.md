# SKILL.md 写作规范（本仓操作版）

> 定位：写/改 `skills/**/SKILL.md` 时按需加载的操作规范。
> 技能创建**流程**见宿主 `skill-creator`；提示词/规则**契约写法**见 `../SKILL.md`；本文只补技能写作面与本仓约束。
> 调研证据与来源：`docs/working/技能与提示词写作_调研_20261113.md`。

---

## 1. 三层分离：角色不进技能

| 层 | 载体 | 写什么 | 不写什么 |
|---|---|---|---|
| 身份/职责 | `config/agents/**` system prompt | 你是谁、职责边界、硬约束、工具面 | 具体操作步骤（归技能） |
| 本次任务 | 任务书 `task_submit` | 目标、验收判据、执行空间、技能指针、禁止面 | 可复用方法论（归技能） |
| 可复用能力 | `skills/<name>/SKILL.md` | 何时用/不适用、输入输出、步骤、脚本、失败分支、验证、gotchas | 你是谁、你在哪执行、本次验收阈值 |

同一个技能要能被不同 agent、不同任务、不同执行空间复用；把角色写进技能会把它绑死在一个执行者上。

## 2. 目录与 frontmatter

```
skill-name/
├── SKILL.md          # 必需：frontmatter + 指令正文
├── scripts/          # 可选：可执行脚本
├── references/       # 可选：按需加载的参考文档
└── assets/           # 可选：模板/样例/数据
```

frontmatter：

| 字段 | 必需 | 约束 |
|---|---|---|
| `name` | 是 | 本仓新技能一律 lowercase kebab-case，与目录名一致（如 `experience-ops`） |
| `description` | 是 | 1–1024 字符，写清「做什么 + 何时用 + 边界」，含触发关键词 |
| 其他 | 否 | 本仓当前只要求上面两项；不强制官方可选字段 |

正文用中文标题（H1）承载显示名；`name` 保持英文标识。

---

## 3. description：触发契约

- 祈使句：`Use this skill when...`，不是 `This skill does...`。
- 写用户意图与适用场景，不写内部实现。
- 略偏「pushy」：列出用户没直说领域名的场景。
- 写明**不适用**边界，防误触发。
- 硬上限 1024 字符；description 是启动时唯一加载的触发信号。

验证：约 20 条真实 query（8–10 应触发、8–10 近似负例），每条跑 3 次，触发率阈值 0.5；按 60/40 拆 train/validation 防过拟合。

---

## 4. 正文：程序，不是宣言

推荐章节（按技能需要取舍）：

1. **用途**：一句话说明能力。
2. **何时使用 / 不适用**：触发与边界。
3. **前置**：环境、依赖、权限、只读/读写面。
4. **输入 / 输出**：字段、格式、路径、体积。
5. **流程**：编号步骤；每步有输入、动作、输出、失败分支、下一步条件。
6. **脚本**：列出 `scripts/` 每个入口与用途。
7. **失败分支**：缺输入、校验失败、依赖不可用、超时、输出过大。
8. **验证**：完成判据、退出码、抽样检查。
9. **Gotchas**：违反直觉的环境事实与项目约定。
10. **参考**：`references/` 文件及何时读。

写法原则：

- 只写 agent 不知道的：每段自问「没有它，agent 会做错吗？」。
- 程序优先于具体答案：教一类问题怎么处理，不写死某次输出。
- 给默认值，不给菜单：多方案时选一个默认，其他一句话带过作为逃生口。
- 按脆弱度校准：容错高的解释「为什么」；脆弱/顺序敏感的写死命令与顺序。
- 高价值结构：Gotchas、Checklist、Validation loop、Plan-validate-execute、Output template。
- 保持精炼：`SKILL.md` < 500 行 / < 5,000 tokens；详细资料拆 `references/` 并写明何时读。
- 不写历史叙事、变更记录、作者心路（归 git/台账）。

## 5. 脚本：给 agent 用

- **禁止交互式提示**：非交互 shell 会挂死；输入走参数/环境变量/stdin。
- `--help` 写清用途、参数、示例、退出码。
- 结构化数据到 stdout（JSON/CSV），进度/警告到 stderr。
- 幂等（create-if-not-exists）；破坏性/有状态操作提供 `--dry-run`。
- 有意义的退出码；缺参给可执行的错误（缺什么、可选值、示例）。
- 输出体积可控：默认摘要/限额，支持 `--offset` 或 `--output`。
- 脚本用相对技能根的路径引用；依赖自包含或明确声明。
- 本仓：不直连活库；口令读 `.env`；只走 REST，不碰 WS。

## 6. 本仓准入与装载约束

1. **`skill_audit` 准入**
   - `scripts/` 下每个附件都必须在 SKILL.md 正文被点名；未声明即拒。
   - 不得有幽灵引用（正文提到但目录不存在的脚本/文件）。
   - 注入/危险命令扫描按入口文档语域执法；外部整包导入用 `doc_scope="package"`。
   - 来源：ADR 2026-10-17-skill-audit-package-scope。
2. **装载面**
   - 任务书/agent 声明 `file_read(path="skills/<name>/SKILL.md")` 懒加载；不常驻注入。
   - `skills/` 是仓内真源；`.zcode/skills/` 同名件只是宿主指针。
   - 任务书只带技能索引指针，不把技能全文贴进任务书。
3. **三层解耦**
   - rule = 跨领域通用常驻纪律（固定注入）；skill = 按任务路由的领域规范/流程（懒加载）；prompt = 角色/硬约束/路由声明（固定注入）。
   - skill 不引用 rule、不复制 rule 正文；通用纪律由 rule 常驻在场。
   - 同一内容只入一边；领域特有规范才进 skill。
   - 来源：ADR 2026-08-24-rule-skill-prompt-decoupling。
4. **打包自洽**
   - 随模式包分发时用 `{{path:./}}` 相对注入；包专属物料不留包外。
   - 来源：ADR 2026-09-29-pack-prompt-material-self-contained。

## 7. 评估：with / without

1. 每条 case：prompt（真实用户口吻）、expected output、可选输入文件。
2. 同一 case 跑两遍：带技能 vs 不带技能/旧版。
3. 断言可验证、PASS 必须有证据：
   - 好：「输出是合法 JSON」「至少 3 条建议」「文件存在且非空」。
   - 弱：「输出很好」「必须出现某句固定文案」。
4. 机械检查用脚本（`file_check/bash_check/artifact_schema_check`），主观质量用 LLM judge/人审。
5. 聚合 pass rate / tokens / time 与 delta；技能价值 = 提升减成本。
6. 迭代：失败断言 + 人审反馈 + 执行轨迹；只做通用修复，不为单例打补丁；越加越差先删。

`skill_audit` 只保证「能进系统 + 声明一致」，不保证输出质量；输出质量另跑上述评估。

## 8. 新建 vs 扩展现有

- [ ] `skills/` 下已有覆盖本次能力 ≥70% 的技能？有 → 扩展，不新建。
- [ ] 只是某现有技能的一步/一段规则？是 → 放该技能正文或 `references/`。
- [ ] 只是「怎么写技能/提示词」？是 → 用 `skill-creator` + `../SKILL.md` + 本文，不新建技能。
- [ ] 新技能有唯一、可判定的触发边界？没有 → 先收敛范围。
- [ ] 已有 agent 会加载它（任务书指针/`file_read` 接线）？没有 → 先接线，避免孤儿技能。
- [ ] 过了 `skill_audit`（脚本全声明、无幽灵引用、无危险命令）？
- [ ] 有 2–3 条真实测试 prompt 与 with/without 对照？

## 9. 反模式

- 技能里写角色、身份、组织关系。
- 技能里写本次任务的验收阈值（归任务书）。
- 泛泛建议：「遵循最佳实践」「适当处理错误」「注意边界」。
- 把某一次的具体答案写死（只对单例有用）。
- 菜单式罗列所有方案，不给默认。
- 过度规定每一步，导致 agent 空转。
- 历史叙事、变更记录、作者心路写进正文。
- 脚本交互式提示、无 `--help`、自由文本输出、无退出码。
- 新增技能不接线、不过 `skill_audit`、无测试 prompt。

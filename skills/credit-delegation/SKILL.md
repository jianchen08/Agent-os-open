# 额度代理方法论（Credit Delegation）

> **本技能是流程指引，不是逐条打勾清单**：按场景判断使用，遇不适用情况保持裁量，不机械执行。

## 为什么需要方法论

很多 AI 工具送额度、闭源、无接口——computer use 是唯一入口。但**裸用 computer use 的 token 成本集中在等待**：目标工具干活是分钟级，若 LLM 每 30 秒 Snapshot 轮询，每次消耗（UIA 树/视觉 token）× 几十次 = 轻松烧掉十万级 token，而真正派发只需十几次调用。方法论的全部目标：**派发成本固定且低，等待成本为零，收割只读一次。**

## 接口优先级（决策树，computer use 永远是最后手段）

1. **原生接口**：CLI / IPC / URL scheme / 本地 API —— 有就直接用（一次 bash 调用 vs 十几次视觉调用）。
2. **文件投递**：目标工具支持打开文件/监听目录（如拖拽区、自动导入）→ 写文件触发。
3. **computer use 派发**：以上皆无的闭源工具，走本方法论三阶段。

## 三阶段协议

### 阶段一：一次性派发（成本固定，≈10-20 次工具调用）

- **任务简报自足**：目标+验收标准+约束+**产出落盘路径**一次写全。目标工具在它的额度里自主干活——不发碎对话，不做交互式来回（每次来回都是一轮 AgentOS token）。
- **产出落文件**（本方法论的核心杠杆）：简报末尾必须约定"完成后把结果摘要/产物写入 `<投递目录>/<约定文件名>`"。这把后续的"读屏"降级成"读文件"——读屏一次几千 token，读文件几乎免费。
- 投递目录约定：`%USERPROFILE%\agentos_dispatch\`（两方都能写的共享路径，按任务名建文件）。
- 派发动作本身按应用档案（见下）执行：聚焦 → 定位输入框 → 输入 → 发送 → 回读确认。

### 阶段二：失聪等待（零 token，时长无关）

派发确认后 **LLM 立即收工**——向用户报告"已派发，预计 X 分钟，完成后我会汇报"，然后结束本轮。等待由非 LLM 机制承担，按廉价程度选信号：

| 信号 | 检查方式 | 成本 |
|---|---|---|
| 结果文件出现 | 触发器定时 file_read/bash 查文件 | ≈0 |
| 进程/窗口标题变化 | bash 查进程名或窗口标题 | ≈0 |
| 剪辑板/剪贴目录 | 同上 | ≈0 |
| UIA 文本标记 | Snapshot（限 region，避免视觉） | 低，仅醒检时 |

用 `trigger_setup` 注册定时触发（间隔=任务预估时长的 1/2，不小于 2 分钟）唤醒自己；每次唤醒**先查廉价信号，信号未出现就直接结束轮次等下次触发**（不 Snapshot、不等待、不占用上下文）。

### 阶段三：一次收割

完成信号出现后：读结果文件（首选）→ 提炼回用户。仅当目标工具不产文件时，才做**一次**最终 Snapshot/截图读屏收割。收割后主动清理投递文件（防下次误读旧结果）。

## 应用档案（App Profile）

每个目标工具一份档案（技能目录），内容五要素：**窗口匹配规则 / 输入定位方式 / 发送动作 / 完成信号 / 结果契约**。档案里未记录的 UI 细节以首跑 Snapshot 实测为准并把实测锚点沉淀回档案。现有档案：
- `skills/zcode-dispatch/SKILL.md`（ZCode）
- `skills/workbuddy-dispatch/SKILL.md`（WorkBuddy）

新增目标工具 = 照五要素写一份档案，不改方法论。

## 失败与安全

- 派发前回读输入内容（防误发）；剪贴板粘贴先告知覆盖。
- 目标工具忙/排队：确认入队后**直接进入失聪等待**——不要在它排队期间反复 Snapshot。
- 目标工具的审批卡/危险按钮：不代批，回报告知。
- 触发器多次唤醒信号仍未出现（超过任务预估 3 倍时长）：停止等待，如实报告"目标工具未在预期时间完成"，不编造结果。

## Token 经济学（为什么这样做）

| 模式 | 派发 | 等待 20 分钟 | 收割 | 总计 |
|---|---|---|---|---|
| 裸 computer use 轮询 | ≈15k | 每 30s 一次快照树/视觉 ≈3-8k/次 ≈ 120-320k | ≈5k | **≈140-340k** |
| 本方法论 | ≈15k | 0（触发器+文件信号） | ≈5k | **≈20k** |

任务越长，差距越大。额度是别人的，token 是自己的——**凡是能用文件和触发器替代的视觉调用，一律替代**。

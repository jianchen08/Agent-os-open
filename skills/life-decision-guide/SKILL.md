# 人生决策：按《高性价比人生指南》查了再答

> 本文件改编自上游 skills/life-decision-guide/SKILL.md（CC BY 4.0，署名与改动
> 声明见同目录 NOTICE.md）。第 0-5 步流程保留上游口径；取文路径改为本仓
> 形态（hindsight recall 知识库主路 + 包内 book/ 兜底），并追加「本地化规则」
> 三条（pim 固化 / 主动时刻 / 一锚一次）。

## 这个 skill 干什么

有人问一件具体的人生事情该怎么办，先去《高性价比人生指南》里把相关条目查出来，再按书里的算账方式排好序回答。

**没查到就别答。** 回答里的每个数字、每条法条、每个结论都要能指回某一条正文；指不回去，就直说书里没写，可以给常识判断，但要标明那是常识不是书里的内容。不要凭记忆补数字、补 DOI、补法条条款号。

书把要换回的东西分成四样：寿命、时间与精力、金钱、人身自由。**四样分开算，不互相折算**——「总死亡率降 12%」和「每年省 500 元」不在一把尺子上。

## 第 0 步：先看要不要马上停下

- **正在发生的急症**（倒地没呼吸、大出血、火灾、溺水、触电、中毒、卒中或心梗的症状）：先说打 120 / 119 和现场第一个动作，出处第 13 节，别先讲性价比。
- **提到自杀念头、活不下去**：先给全国心理援助热线 12356，再按第 1 节和第 29 节里的条目说，不做劝导式分析，不评价动机。
- **正在进行的法律程序**（已被传唤、已被拘留、已被起诉）：先指第 8 节对应条目，并说明书只给通用口径，个案要找律师。
- 其余情况，照下面的步骤走。

## 第 1 步：把正文拿到手

三种来源按优先级试，对上哪种就用哪种。

**① hindsight recall 知识库（主路）**：全书 34 章已入 AgentOS 知识库（hindsight 原生管线，原文直存）。用 `hindsight.recall` 工具检索：

- 先查主 bank：`hindsight.recall(query="<用户问的事的关键词>", bank_id="kb", tags=["type:knowledge"], tags_match="all", top_k=5)`。返回条目的 `name` = 章节文件名（标题归属），`content` = 原文片段，`tags` 含摄取实体标签。
- 主 bank 空结果或报错 → 再查降级 bank：`bank_id="kb_chunks"`（verbatim 不可用时条目落这里，其余参数同上）。
- recall 返回的是片段；引用数字、法条、来源前对照片段完整性，条目被截断就落到②按文件读整条。

**② 包内 vendor 正文（兜底）**：本技能目录旁的 `book/` 就是全书 34 章（`book/01-不要早死.md` … `book/34-家里的常备药别吃出事.md`）。recall 不可用或片段不够时，直接用文件工具读 `book/` 下对应章节。下面各步的 grep/sed 命令都在本技能目录（`skills/life-decision-guide/`）下跑。

**③ 远程现取（末路）**：前两条都不可用才用。浅克隆一次最省事：

```bash
git clone --depth 1 https://github.com/eternity4719/HowToLiveBetter.git "${TMPDIR:-/tmp}/hltb"
```

不能用 git 时按文件取：

```bash
curl -fsSL --compressed "https://raw.githubusercontent.com/eternity4719/HowToLiveBetter/main/book/02-不要慢慢死.md"
```

三条都走不通，就说明取不到正文，如实告诉用户，不要凭印象复述书的内容。

## 第 2 步：定位到节

先挑 1 到 3 节：`book/` 下文件名自带节号和节名（`ls book/` 能看全），按用户问的事对上号——例如吃药看「34-家里的常备药别吃出事」，租房看「15-租房与买房」，担保借贷看「08-别把自己搭进去」。

节的归属拿不准时按关键词先搜正文标题再定节（见第 3 步第一条命令），不要凭节名猜。

## 第 3 步：把条目捞出来

vendor 包不带索引文件，直接按条目标题搜正文：

```bash
grep -rn '^### ' book/ | grep -E '关键词1|关键词2'        # 先看有哪些条目标题
grep -rn -B2 -A8 '关键词' book/08-别把自己搭进去.md        # 正文里搜，带上下文
sed -n '/^### 16\. /,/^### 17\. /p' book/08-别把自己搭进去.md  # 按条号抽一整条
```

走 recall 主路时同理：query 先用「用户问的事」原话试一轮，命中差再换条目级关键词（如「健身卡」「低钠盐」「担保」）补一轮。

**抽出来的条目要整条读完**，尤其是「备注」栏——适用人群、争议、例外都写在那里，只读标题会把条件丢掉。

一条长这样：

```markdown
### 5. 把家里的食盐换成低钠盐（钾盐）
<!-- 成本标签: 钱=少 时间=少 毅力=否 收益=中 口径=死亡率 -->
- 成本：每袋贵几元
- 说人话：……死亡的概率低约 12%……
- 收益：脑卒中降 14%，心血管事件降 13%，总死亡率降 12%
- 证据等级：A
- 来源：Neal B, et al. (2021). NEJM. https://doi.org/10.1056/NEJMoa2105675
- 备注：争议。肾功能不全、正在吃保钾利尿剂的人不要用。……
```

那行 HTML 注释是给机器读的成本标签：钱 0/少/多、时间 少/中/多、毅力 否/些/是、收益 大/中/小、口径 死亡率/金钱/时间/自由。少数条目末尾还有 `人群=`（怀孕、婴幼儿、孩子、老人、35岁、60岁、女性，逗号是或、加号是且），表示只对这些人有用；用户明显不在那个人群里时，这条可以不推荐。

## 第 4 步：排序

1. 按收益量级与成本标签对照（书自己的口径：收益 大 > 中 > 小；成本 = 钱 + 时间 + 毅力三项合计，少者优先）。性价比档位表不在本包内，**勿凭记忆报「性价比极高/高/一般」档**。
2. 先按收益量级，同档再按证据等级 A > B > C，再按跟用户处境的贴合度。
3. **不同口径之间不排序**。换钱的和换寿命的分开列，各排各的。
4. 收益量级是作者的判断，按书自己的标准只算参考；它和证据等级是两回事，别混。

## 第 5 步：怎么写这份答复

1. **一句话结论**：这件事划不划算、该不该做、第一步是什么。
2. **先做这几条**（3 到 7 条，按上面的序）。每条一行到三行：动作（动词开头）、花掉什么、换回什么、证据等级、出处写成「第 8 节第 17 条（借条和担保）」，括号里的词取自条目标题，方便用户自己翻。
3. **别做 / 不用做的**：书里明确说不值得或有反面证据的，单列出来。
4. **书里没写的**：如实说，不要拿常识冒充书的内容。
5. 需要的话补一句复查点：什么时候回头再看一次，或者什么信号出现就改主意。

写的时候守住这几条：

- **落到谁身上要说清**。书把受益人分四档，按好处回到自己身上的可能性从高到低：① 你自己；② 配偶和直系亲属；③ 朋友、同事和其他亲属；④ 陌生人。写到第 ④ 档（救陌生人、替人担保、帮人转账）要把风险面和好处一起写：被讹、被卷进案子、被报复，不能只写好处，也不能写成一律别管。
- **「法律支持你」的事必须连过程成本一起说**。只说结果不说过程，等于把胜诉率当成收益。要交代要不要打官司、大概多久（一审普通程序按规定 6 个月内审完、可以延长，简易程序 3 个月，这是法定审限不是实际耗时）、律师费谁掏（律师费不在诉讼费用里，败诉方负担不包括它）。
- **数字照抄条目**，一个不改。条目里写了置信区间、人群、年份就一并留着；HR、RR、OR 这类写法旁边就地翻成「低约 28%」，原值不删。条目里没有的数字、症状、机制解读一律不加。
- **口语化**：按没受过专业训练的成年人能一遍读懂来写。专业名词当场用日常话解释一句，法条落到「会摊上什么后果、该怎么做」。来源栏照原样给，方便核对。
- **语气克制**，不说教，不用感叹号，简体中文。用户不按建议做是他自己的事，不追着劝。
- **政策会变**：第 7、19、21、24、31、32 节里那些金额、时限、名单，正文写了截至日期，答复里把日期带上并提醒用户自查官方渠道。
- 有「争议」标注的条目，把反方证据也说一句；标了「TODO 待核实」的，别当结论用。
- 不引知乎、公众号、搜狐这类二手转述，只给条目「来源」栏里已有的链接。

## 本地化规则（AgentOS 个人助理模式，三条）

以下三条是本仓新增口径，上游 SKILL 无此内容。pim 工具即本模式包的待办/日程/习惯工具（capture 一句话建卡）。

### 规则① 用户认可建议 → 提议经 pim capture 固化，卡面写 guide_ref

用户对某条建议表示认可、愿意照做时，**提议**把它转成 pim 卡（习惯用 habit、一次性动作用 todo），**用户点头才建，不擅自建卡**。建卡时把条号写进卡面 `guide_ref` 锚——格式与答复出处一致：`guide_ref: 第 8 节第 17 条`，一句话一句话带在卡标题尾部或备注里均可，但要能按字面 grep 到（如「(guide_ref 第 8 节第 17 条)」）。这样卡面永远能指回书里的原始条目，后续复盘照条号回查原文。

### 规则② 三个主动时刻（按域喂条，每处有上限）

- **晨报**：组装晨报时，按未决事项所属域（健康/金钱/法律/安全/学习——recall 实体标签同域）从指南 recall 挑 **≤1 条** 相关建议，带出处与争议标注；未决事项为空或不相关就不喂。
- **周复盘**：周复盘由 repeat weekly 周期卡承载（pim 卡 `repeat: weekly:<0-6>`）；复盘会话里从本周完成/放弃的事项对照指南挑 **≤2 条**，说清「书里的对应做法」与差异即可，不铺开全书。
- **事件规则**：习惯连击（streak）断 **≥2 天** 时，主动对照指南该习惯所属域的条目一次，给一条最相关的做法或「书里怎么说过」；断 1 天不触发。

三个时刻共用第 0 步闸门：急症/危机情形永远优先于任何主动喂条。

### 规则③ 一锚一次（防重复喂）

`guide_ref` 已在卡面 = 这条建议已经喂过，**同一条不再向同一用户重复主动推送**（晨报、周复盘、事件规则三处都受此约束）。用户主动再问同一条时照常回答——约束的只是主动推送面。新条目才允许进入主动时刻的候选。

## 边界

这本书给的是通用口径，不替代医生、律师、会计。涉及具体病情、具体案件、具体税务的，按书里的条目给方向和该找谁，别替专业人士下判断。不给个性化投资建议。

书的观点是作者的，性价比档怎么划也是作者的判断。用户不同意某一条时，把书里的依据摆出来就够了，不辩论。
